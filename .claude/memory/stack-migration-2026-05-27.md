On 2026-05-27 the user scrapped the **entire** former .NET 10 / Aspire / EF / MCP / observability stack (they were "not happy with outcome") and rebuilt Kairos as a **Next.js 15 App Router** app (TypeScript, Tailwind v3, Server Actions) backed by **Supabase (Postgres)** and deployed to **Vercel**, with **GitHub Actions as the sole deployer** (all Supabase/Vercel credentials live in GitHub Actions secrets; app runtime secrets live in Vercel env). The repo is **PUBLIC** — never commit secrets.

Initial scope: **core schedule MVP** — tasks + time-blocked day view + free-slot suggestions + drag-to-reschedule. It has since grown (still single-user, still simple): **5-day / week / month** views, **recurrence** (daily / weekdays / weekly / every-N) with a series-delete confirm, **checkpoints** (named moments on the grid), **labels + time budgets** (a `/settings` room), a **timezone toggle** (Karachi ↔ UTC; storage stays UTC), and **read-only Google Calendar sync** (shipped 2026-06-02; see below). Auth: a **single-password gate** now fronts the app (`APP_PASSWORD` + `AUTH_SECRET`, lockout after repeated failures) — still **not** multi-user accounts. The DB stays hardened (RLS on with zero policies; all access via the **server-only service-role key**, never shipped to the browser, no `NEXT_PUBLIC_*` Supabase vars).

**Google Calendar sync shipped 2026-06-02** (user opted back in, overriding the earlier drop). Read-only, **multi-calendar**, attached by each calendar's **secret iCal URL** + a label — **no OAuth, no Google Cloud project**. `ical.js` (the one added dependency) expands recurrence; a persisted sync reconciles events into `scheduled_blocks` as `source='gcal'` rows over a `today −7d…+60d` window. New `calendars` table + `scheduled_blocks.calendar_id`/`title`. They render in cool graphite (the `--gcal` token / `.block-gcal`, "Borrowed-Time Rule"), read-only, overlap-exempt, and count as busy for free-slots. Files: `src/lib/ics.ts`, `src/server/calendars.ts`, `src/server/calendar-sync.ts`, `src/components/CalendarManager.tsx`. Workspace admins can disable secret iCal addresses — if so, only OAuth (not built) would work for that calendar. Full guide: `docs/GOOGLE_CALENDAR.md`.

Still deliberately dropped / deferred (do **not** reintroduce without asking): the MCP server, the OpenTelemetry/Grafana observability stack, Docker Compose/reverse proxy, and **multi-user accounts** (the single-password gate is the only auth). Note: recurrence **shipped** as fixed presets, not open RRULE editing, so don't reach for a full RRULE engine for *Kairos tasks* without asking (the iCal RRULE expansion is read-only, for incoming Google events only). The Postgres-native design carried over: generated `during` tstzrange, `EXCLUDE USING gist` no-overlap constraint, and the `free_slots()` multirange SQL function.

**Why:** user wanted it simple, public, and cheap to run on one Vercel project.
**How to apply:** see [UI redesign direction](ui-redesign-direction.md) for the look; treat the dropped features as future opt-ins and confirm before adding any back; CLAUDE.md is the authoritative in-repo guide. The app is now [deployed & live](deployment-live.md).
